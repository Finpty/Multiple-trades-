# Database

PostgreSQL 14+ is the canonical database. Prisma (`prisma/schema.prisma`) owns
the schema; migrations live in `prisma/migrations` and are applied with
`pnpm db:migrate` (deploy) or `pnpm db:migrate:dev` (development).

## Conventions

| Concern            | Convention                                                        |
|--------------------|-------------------------------------------------------------------|
| Tables             | snake_case via `@@map`; columns camelCase (quoted identifiers)    |
| Primary keys       | `uuid` from `gen_random_uuid()`                                   |
| Timestamps         | `timestamptz(6)`; `createdAt`/`updatedAt` on mutable tables       |
| Money              | integer cents (`*Cents`); rates as `numeric(14,4)`                |
| Configuration      | `jsonb` columns validated by zod at the application boundary      |
| Enumerations       | native Postgres enums                                             |
| Soft delete        | `deletedAt` on important records; status enums for lifecycle      |
| Tenant column      | `businessId uuid` on every tenant-owned table                     |

## Tenant boundaries

Three tiers of tables:

1. **Platform tables** (no RLS): `users`, `sessions`, `auth_tokens`,
   `oauth_accounts`, `passkeys`, `rate_limit_buckets`, `roles`,
   `organizations`, `organization_memberships`, `businesses`,
   `business_domains` (the lookup boundary), `industries`, `business_templates`,
   `design_families`, `feature_definitions`, `platform_settings`.
2. **Tenant tables** (forced RLS, `businessId NOT NULL`): everything owned by a
   business — services, pages, media, customers, quotes, jobs, forms, …
3. **Mixed tables** (forced RLS, `businessId` nullable): `audit_logs`,
   `domain_events`, `integrations`, `api_keys`, `ai_providers`, `ai_usage`,
   `notifications`, `subscriptions`. Rows with `businessId IS NULL` are
   platform-level and only visible with bypass or `app.allow_platform_rows`.

## Row Level Security

`prisma/migrations/*_rls/migration.sql` (generated by `pnpm db:rls`) enables
and **forces** RLS on every table with a `businessId` column and creates one
policy per table:

```sql
USING (
  app_rls_bypassed()                                   -- platform/system
  OR "businessId" = app_current_business_id()          -- tenant scope
)
```

Settings are transaction-local (`set_config(..., true)`), so a pooled
connection never leaks a tenant into the next query.

| Client                     | Setting applied                     | Use                                  |
|----------------------------|-------------------------------------|--------------------------------------|
| `prisma`                   | none → sees **no** tenant rows      | platform tables only                 |
| `tenantDb(businessId)`     | `app.current_business_id`           | all tenant code                      |
| `platformDb`               | `app.bypass_rls = on`               | after `requirePlatformAdmin()`; jobs |
| `withTenantTransaction()`  | tenant setting for the whole tx     | multi-statement tenant writes        |
| `withPlatformTransaction()`| bypass for the whole tx             | business creation, seeding           |

When adding a model with `businessId`, run `pnpm db:rls`, save the output as a
new migration and apply it. The verification script
`scripts/verify-foundation.ts` asserts isolation.

## Query rules

- Never call `prisma.<tenantModel>` directly; use the client from
  `requireBusinessAccess()` or `tenantDb()`.
- Never accept `businessId` from the client without going through
  `requireBusinessAccess()`.
- Soft-deleted rows are hidden automatically from find/count/aggregate; pass
  `where: { deletedAt: { not: null } }` (or `deletedAt: undefined`) to include
  them explicitly.
- Cross-tenant operations (duplicate, templates, platform reports) run under
  `platformDb`/`withPlatformTransaction` **after** platform authorization and
  are audited.

## Admin override strategy

Platform OWNER/ADMIN users get every business permission through
`getBusinessAccess()` (`viaPlatform: true`). The UI shows an override banner;
actions are audited with `actorType = USER` and the business id, so a tenant
can see when platform staff acted in their account.

## Audit strategy

`audit_logs` is append-only. `recordAudit()` redacts secret-like keys, never
throws into business logic and captures actor, organisation, business, action,
entity, before/after, IP, user agent and severity. Security-sensitive actions
(login failures, password resets, role changes, domain changes, publishes,
platform setting changes) use `NOTICE`/`WARNING`/`CRITICAL`.

## Retention and partitioning

`audit_logs`, `domain_events`, `analytics_events`, `ai_usage` and `messages`
are indexed by `(businessId, createdAt)` and can be range-partitioned by
`createdAt` without application changes. Expired sessions, tokens and
rate-limit buckets are purged by `purge*` helpers (wire to a cron).

## Running locally

```
createdb tradeone
pnpm setup      # prisma generate + migrate deploy + seed
```

`SHADOW_DATABASE_URL` is only needed for `prisma migrate dev`.
